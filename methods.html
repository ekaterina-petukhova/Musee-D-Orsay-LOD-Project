01 · E/R Model

Entity–Relationship Model

The relational view below is intentionally simplified and visually aligned with the reference project: it presents the main entity categories, a small set of representative attributes, and the key relations around the museum. It is a schematic E/R overview, distinct from the detailed theoretical model, schema-level conceptual model, and instance-level RDF graph.

E/R Model — Entity · Relationship · AttributeOpen full screen ↗

Entities are rectangles, relationships are diamonds, and descriptive attributes are ovals. Fourteen selected research entities appear with supporting context (the transformation event, adaptive reuse, ICOM, and the digital platform). Drag to pan and use the zoom buttons or mouse wheel to inspect details.

Representative relationship examples: museum ↔ person, museum ↔ event, museum ↔ place, museum ↔ organisation, museum ↔ concept, and event ↔ place. Full project relations remain available in TheoreticalModel.csv and in the RDF dataset.

02 · Metadata Alignment

Metadata Analysis & Alignment — WHO / WHAT / WHERE / WHEN

Metadata alignment connects descriptive questions — WHO participates, WHAT is represented, WHERE a resource is identified or located, and WHEN events occur — with concrete predicates from the project’s RDF dataset. Unlike a generic crosswalk, the table below lists actual implemented predicates, how they are used, and the number of triples in the present Turtle file.

The project currently reuses CIDOC CRM, Schema.org, DCTerms, FOAF, SKOS, OWL, RDF and RDFS, plus custom ex: properties. MARC21 and other crosswalk standards are not claimed as implemented unless they actually appear in RDF. WHO/WHAT/WHERE/WHEN are analytical groupings, not ontology classes; some predicates span more than one dimension.

05 · Reproducible Workflow

Data Pipeline and Deliverables

Wikipedia article → selected TEI source paragraphs (tei.xml) → Python transformation → RDF/Turtle (rdf.ttl) → interactive Knowledge Graph.

The same TEI also produces annotated HTML through tei_to_html.py. The repository includes an XSLT alternative in tei_to_html.xsl. The theoretical and conceptual diagrams are generated from their own CSV descriptions, not from the TEI body.

Current parsed state: 29 project entity records; 210 RDF triples; 10 distinct inline entity references. The primary TEI body contains selected Wikipedia sections, not a proven complete edition of the full Wikipedia article; verify against the source before assessment.
